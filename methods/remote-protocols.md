# Remote protocol and session method

How to judge the way users' sessions reach their hosts: which transport RDP uses and why, what keeps a session alive when a path fails, and the session settings that ride on the transport (redirection, graphics, Teams and media, time limits). It is the [assessment](assessment.md) method applied to the remote protocol and session pillar (`protocol` in `dimensions.yaml`). Almost all of it is documented by Microsoft, so the method links out to those pages and adds only the transport map and the scope page (`gap:transport-classification`, `gap:remote-protocols-scope`). The networking pillars own how the network provides what RDP needs; this page states what it needs.

## Method

1. **Ask how users connect** before reading anything: managed networks (ExpressRoute or VPN), public networks, or both, and which clients they run. The intent decides what a good outcome is (`gap:remote-protocols-scope`, `ref:review-checklists-avd#C02.05`).
2. **Read the host pool's switches:** the four Shortpath options are Default (enabled), Enabled or Disabled, and UDP over Private Link is a separate opt-in that is off unless set. All of them are readable only through a preview API version, so a GA read leaves them `unknown` (`ref:configure-rdp-shortpath#hostpool-switches`, `ref:hostpool-api-changelog#udp-switches-preview-only`, `ref:hostpool-api-changelog#private-link-udp-preview-only`, `ref:avd-private-link#udp-opt-in`).
3. **Check the host side** where a host read exists: UDP not forced off by policy, and for managed networks the listener and its inbound port (`ref:configure-rdp-shortpath#select-transport-policy`, `ref:configure-rdp-shortpath#listener-for-managed`, `ref:configure-rdp-shortpath#most-restrictive-wins`, `ref:review-checklists-avd#F01.11`).
4. **State what RDP needs from the network** and hand it to the networking pillars: outbound UDP from hosts, the TURN range on UDP 3478, the client port range, no proxy or inspection as the only path, and several ports per session (`ref:avd-proxy#proxy-forces-tcp`, `ref:rdp-shortpath#turn-range`, `ref:rdp-shortpath#public-network-advice`, `ref:configure-rdp-shortpath#port-range`, `ref:rdp-multipath#ports-per-session`).
5. **Read what each connection used** from the logs, through the family's transport map, never one table's vocabulary alone; Insights' connection reliability view shows Multipath too (`gap:transport-classification`, `ref:wvdconnections-table#transport-type`, `ref:rdp-multipath#verify-in-insights`, `obs:transport-column-names-disagree`).
6. **Judge each connection against the intent and the host egress:** UDP where expected passes, TURN behind symmetric NAT egress (both landing zone network modes) passes, TURN where a direct path was expected or TCP after UDP was possible is a warn, and UDP turned off with no reason is a gap. TURN doesn't exist in Azure Government. Where UDP fails, point the operator at the NAT type test and the Shortpath error codes (`gap:remote-protocols-scope`, `ref:rdp-shortpath#tcp-first-then-udp`, `ref:rdp-shortpath#stun-before-turn`, `ref:rdp-shortpath#symmetric-nat-means-turn`, `obs:symmetric-nat-egress-means-turn`, `ref:configure-rdp-shortpath#turn-public-cloud-only`, `ref:troubleshoot-rdp-shortpath#nat-type-test`, `ref:troubleshoot-rdp-shortpath#udp-error-codes`).
7. **Check the clients** against the platform table and the Multipath and auto-reconnect floors; the web client never uses Shortpath (`ref:windows-app-platforms#shortpath-by-platform`, `ref:rdp-multipath#client-floors`, `ref:avd-auto-reconnect#needs-multipath`).
8. **Read latency and quality** from the network and graphics data: RTT against the published bands, and frame drops by cause. Jitter and loss stay `unknown`, because no AVD table reports them (`ref:avd-insights-use-cases#rtt-ideal-100-poor-200`, `ref:wvdconnectionnetworkdata-table#rtt-and-bandwidth-only`, `ref:wvdconnectiongraphicsdata-table#frame-drops-by-cause`).
9. **Judge QoS and throttling only on managed-network UDP,** the one transport that supports them (`ref:rdp-qos#managed-udp-only`, `ref:rdp-qos#dscp-46`, `ref:rdp-bandwidth#throttle-managed-only`).
10. **Check graphics settings against the hardware:** CPU encoding by default, AVC 444 only with hardware encoding, HEVC only on GPU desktops without multimedia redirection (`ref:graphics-encoding#software-default`, `ref:avd-gpu-acceleration#avc444-needs-hw-encoding`, `ref:avd-gpu-acceleration#hevc-prerequisites`, `ref:graphics-chroma-444#only-support-verifies`).
11. **Check the session settings that ride on the transport:** redirection per kind (new pools start with clipboard, drives, USB and printers off), Teams media optimization and multimedia redirection, disconnected-session time limits and lock behavior (`ref:rdp-properties#redirection-properties`, `ref:avd-whats-new#redirections-off-new-pools`, `ref:rdp-redirection#high-level-first`, `ref:teams-on-avd#media-optimization`, `ref:multimedia-redirection#video-playback`, `ref:autoscale-faq#disconnected-time-limit`, `ref:session-lock-behavior#disconnect-on-lock-sso`).
12. **Record what stays `unknown`** and why: no host read, a GA API read, no diagnostic settings, or no operator answer (`gap:remote-protocols-scope`, `ref:connection-quality-data#diagnostic-tables`).

## Not yet known

- Which log column a real workspace carries (`obs:transport-column-names-disagree`), and how much round-trip time a TURN relay adds over a direct path, and whether egress firewalls allow it at all (`obs:symmetric-nat-egress-means-turn`). One short sandbox run with a client device settles both; it waits on a cost estimate and the owner's go.
- What share of connections should end up on each transport in a healthy estate. No source publishes one; evidence submissions can (`gap:evidence-intake`).
- No check runs yet. The host pool switches need a C11 fact read through a preview API version, and the per-connection outcome needs C12 facts; both are proposed in `dimensions.yaml`.
