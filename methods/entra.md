# Entra ID and identity method

How to judge the identity control plane of an Azure Virtual Desktop estate: session host join type, single sign-on, Conditional Access for sign-in, Azure Files Kerberos identity, application group assignments, and administrative role boundaries. It is the [assessment](assessment.md) method applied to the identity pillar (`identity` in `dimensions.yaml`) and the Entra ID control plane (`entra`). Microsoft documents each identity requirement, so this method links to those sources and adds only the scope page (`gap:identity-scope`): which Microsoft Graph reads and Azure control-plane facts are collected and how they combine with operator intake.

## Method

1. **Ask the identity questions the directory and control plane cannot answer** before judging the estate: whether Active Directory or Entra Domain Services must stay, which user identity source and join type are intended, where MFA applies, which client devices connect, which sign-in methods are used, and whether external users sign in (`gap:intake`, `gap:identity-scope`, `ref:avd-prerequisites#identity-scenarios`).
2. **Check that each host pool uses one supported session host join type** by comparing the Entra join and domain join VM extension counts on its session hosts (`ref:avd-entra-joined-hosts#one-join-type-per-pool`, `ref:review-checklists-avd#D03.02`, `gap:identity-scope`).
3. **Check single sign-on across both halves of the configuration:** the host pool's `enablerdsaadauth` RDP property in the Azure plane and the Windows Cloud Login service principal and dynamic device group in the Entra plane (`ref:avd-sso#host-pool-property`, `ref:avd-sso#tenant-rdp-enabled`, `ref:avd-sso#consent-prompt`, `ref:review-checklists-avd#D03.04`, `gap:identity-scope`).
4. **Check Conditional Access policies targeting the AVD service and Windows Cloud Login:** require multifactor authentication, align sign-in frequency and session lock behavior, and keep the feed discovery and Azure Windows VM Sign-In apps out of policies that would break passwordless sign-in or feed refresh (`ref:avd-mfa-conditional-access#target-apps`, `ref:avd-mfa-conditional-access#two-aligned-policies`, `ref:avd-mfa-conditional-access#feed-app-no-mfa`, `ref:avd-entra-joined-hosts#vm-sign-in-app-exclusion`, `ref:review-checklists-avd#G04.01`).
5. **Check that every enabled AVD Conditional Access policy excludes emergency-access (break-glass) accounts or groups** so a conditional-access misconfiguration or provider outage cannot lock administrators out of the tenant (`ref:ca-require-compliant-device#exclude-break-glass`, `ref:mcsb-avd-baseline#IM-7`, `gap:identity-scope`).
6. **Check Azure Files identity-based authentication and its Entra Kerberos service principal:** when a profile storage account uses `AADKERB`, verify that its Entra service principal exists in the directory and is excluded from Conditional Access policies that require interactive MFA (`ref:files-entra-kerberos#cloud-only-and-hybrid`, `ref:files-entra-kerberos#exclude-from-mfa`, `ref:review-checklists-avd#D02.01`, `gap:identity-scope`).
7. **Check application group assignments and administrative role boundaries:** assign `Desktop Virtualization User` to Entra groups rather than direct users, and separate administrative access with scoped AVD roles below Owner and Contributor (`ref:avd-rbac#user-role`, `ref:avd-rbac#scoped-roles`, `ref:caf-avd-identity#groups-not-users`, `ref:review-checklists-avd#D01.06`, `ref:review-checklists-avd#G03.06`).
8. **Score Entra checks as not applicable only when the Entra plane is skipped** (`planesCollected.entra.status != "collected"`), and record what stays `unknown` when a directory read is absent (`gap:identity-scope`, `gap:scoring`).

## Not yet known
