# Gap: assessing the networks users connect from

**Searched (2026-10-21):** the client endpoint list (`ref:avd-required-fqdn#client-list`), the Private Link client connection sequence (`ref:avd-private-link#client-dns-sequence`), the proxy page's client section (`ref:avd-proxy#client-proxy-support`), the round-trip target (`ref:avd-prerequisites#rtt-under-150`) and the checklist's proof-of-concept item (`ref:review-checklists-avd#C02.04`). **Not found:** a method for judging a user network before users move, a test that a user network resolves AVD's private names, or guidance on device-side VPN, security service edge and zero-trust agents beyond the platform address rule for hosts (`ref:avd-fabric-ips#never-proxy-or-tunnel`).

**What we write.**

1. **One intake entry per user network** (office, branch, home, guest, partner, other), built in C19 as `intake.userNetworks`: banded sample count (`1-2`, `3-9`, `10-25`, `26-100`, `100+`), whether it allows the client endpoint list, whether outbound UDP is allowed, whether a proxy or inspection sits in the path, whether a device VPN or agent tunnels AVD traffic, round trip and jitter to the candidate regions measured from that network, never from Azure (`obs:region-latency-from-the-user`), and optional banded user sentiment (`ratingMedian` 1 to 5, `lowRatingShare` 0 to 1, and enumerated symptom chips).
2. **Private Link from the client is a per-network test.** Where users must connect privately, a person on each network resolves the discovery, feed and gateway names and compares the answers with the endpoint addresses; any public answer is `warn`. Global discovery is public by design (`ref:avd-private-link#global-workspace`), so "fully private" is never an outcome.
3. **Mixed feeds.** A network with no internet access and users subscribed to public and private feeds is `warn` for the Windows Remote Desktop client (`ref:avd-private-link#mixed-feed-limit`).
4. **Device agents.** The row `network.client-agents` holds the SSE, ZTNA and VPN client categories, web proxies and TLS inspection on user devices: RDP split out of every tunnel, uninspected and leaving the user's network locally (`ref:rdp-traffic-optimization#bypass-tunnels`, `ref:rdp-traffic-optimization#no-tls-inspection`, `ref:rdp-traffic-optimization#local-egress`). Found after this page's search, on a Windows 365 page that covers AVD's ranges too. Categories only, never products; the agents on the hosts and the rest of the category work are in `gap:security-agents-scope`.
5. **Which endpoints, probed from where.** The endpoint map (`gap:endpoint-map`) names the client rows a browser or a native tool on the device can probe and the ones no probe can reach by name; an avd-linecheck export answers the endpoint, region, proxy and user sentiment questions above for one network on one day.
6. **Deterministic user sentiment and symptom mapping.** `avd-linecheck` exports optional structured sentiment (`rating` 1 to 5 and seven closed symptom chips, never inferred from free text). Multiple exports aggregate into `intake.userSentiment` (estate-wide rollup) and per-network `intake.userNetworks[*].sentiment`, while the seven `avd-linecheck` chips map deterministically into `intake.reportedSymptoms` (`gap:diagnostics-scope`): `sign-in` maps to `sign-in-fails`; `disconnects` maps to `disconnects`; `slow-typing`, `frozen-blurry-screen`, `teams-audio-video`, `printing` and `slow-apps` map to `slow-session`.
7. **Measured, not assumed.** After users move, Insights round trip and transport per client network replace the intake answers (the remote protocol pillar reads transport; this pillar reads where it failed), and comparing `intake.userSentiment` against measured check outcomes surfaces perceived-versus-measured blind spots.

Nothing here is automated in Azure: it runs on users' devices and networks, so it is intake or a reviewer's test, recorded with the date, the sample band and the network kind, never a user or device name.
