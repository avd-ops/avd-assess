# Gap: one endpoint map that every family probe reads

**Searched (2026-10-21):** the required endpoint page (`ref:avd-required-fqdn#client-list`, `ref:avd-required-fqdn#host-list`, `ref:avd-required-fqdn#service-and-fqdn-tags`), the platform address page (`ref:avd-fabric-ips#two-platform-ips`), the Agent URL Tool page (`ref:avd-url-check-tool#run-on-host`, `ref:avd-url-check-tool#wildcards-not-checked`), and Learn for a machine-readable list of AVD's names. **Not found:** a published file of AVD's names that a tool can read (the service tag file carries addresses, not names, and the Agent URL Tool keeps its list inside the agent and checks no wildcard); any guidance on which endpoints a probe can test from where; and any rule for which failed probe should change a tool's overall verdict.

**What we write.** (Network endpoints, the names and ports AVD traffic needs; the user devices themselves are the `endpoints` pillar.) [endpoints.yaml](../endpoints.yaml), built into [endpoints.json](../endpoints.json) (contract C20, `avd-assess-endpoints/v1`), is a map in the sense of [CLAUDE.md](../CLAUDE.md): one row per endpoint a family tool probes or must report as not tested, each pointing at the pinned Learn claim that lists it. A row carries only what a probe needs from Microsoft's table (the name, protocol, port and, where the table gives one, the service tag) plus the fields below; purposes are our own words, Microsoft's descriptions, notes and other clouds stay on the page, addresses and ranges are never restated, and the page at the pin stays the authority. A list may cover every row of a Microsoft table when a tool must account for every row. What a row adds:

1. **Where a probe means something** (`probeFrom`). `browser` is a web page on the user's device, HTTPS on TCP 443 only (a page served over HTTPS can't fetch plain HTTP); `device` is a native tool on the user's device; `host` is a session host. A probe from anywhere else, Cloud Shell or the operator's machine included, is `unknown`, never `pass` ([network-scope.md](network-scope.md) item 3, `obs:endpoint-probe-off-host`). Only concrete names have a `probeFrom`. Wildcards, the relay range and the two platform addresses never do (the map carries no address; the platform addresses are judged by configuration, `ref:avd-fabric-ips#no-deny-no-route`), so a tool lists them under what it did not test.
2. **Whether a failure moves the verdict** (`verdict`). Microsoft supports no deployment that blocks any listed endpoint (`ref:avd-required-fqdn#blocking-unsupported`), so every row stays required by Microsoft. `informational` says only that a lone failed probe from a user's device is more often a proxy, content blocker or redirect than a broken connection, so it gets its own sentence and never moves the overall verdict. Readers go by the `verdict` field, never by `purpose`. On the user's device it marks required the sign-in name, `windows.cloud.microsoft` and the service wildcards, as the landing zone portal already does; on a host it marks required everything except the name Learn lists for Azure Local only, because a host has no such excuse.
3. **Kept current by a test, not by memory.** `readAt` names the Learn git_commit_id of every page a list or a note cites, as read for this map. The weekly pins workflow reports a moved page as an issue; when a person moves the reference's pin, `tests/check_endpoints.py` fails until the rows and `readAt` are updated from the page at the new pin. Renaming or removing a row bumps `version`; readers key on row IDs.
4. **One cloud per map.** This map is the Azure public cloud. Azure for US Government has its own lists on the same page; a map per cloud is the extension point, not a switch inside this one.

**Left out on purpose.** The page's optional "other endpoints" table and the Intune Remote Help endpoints (no family tool probes them yet); names Learn no longer lists (avd-current-state probes three older broker and gateway names; the avd-linecheck spec, Q5, waits on its spike before deciding); and redirect targets, which depend on what a host answers on the day and belong to the reader's own pack.

**How readers use it.** Nothing fetches the map at run time. A reader vendors `endpoints.json` at an avd-assess commit with its SHA-256, the way the foundation contracts are vendored ([contracts/README.md](../contracts/README.md)), and reads `views.<vantage>`: `lists` (the lists that vantage judges), `probe` (the rows it may probe) and `notTested` (every other row of those lists, for its "not tested" list). A reader that meets a field it doesn't know ignores it.

|---|---|---|
